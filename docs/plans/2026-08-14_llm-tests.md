# LLM-specific test plan (D2)

Date: 2026-08-14
Owner: Ben.
Status: Plan — captured before writing the tests.

## Why

The live OpenRouter smoke-test caught three real bugs the initial 5-test
`tests/llm_e2e.rs` suite missed (missing field in reply, model couldn't see the
owner's ask, double-audit of a failed pass). This plan closes the gaps so the
integration is pinned down without needing a live key / spend in CI. All tests
below run against a **local stub OpenAI-compatible `chat/completions` server**
(no live call, CI-safe), plus one opt-in live test Ben can run locally.

## What a correct integration must guarantee

1. **Protocol/transport** — the request is a valid OpenAI-compatible
   `chat/completions` POST: correct URL (`{base}/chat/completions`), bearer
   auth, `model`, system+user messages, json-object response mode.
2. **Prompt contract** — the model is told the required FIELDS per action and
   the enum values, i.e. the prompt does not drift from the real `PmAction`
   serde shape (the bug that caused `missing field 'to'`).
3. **The owner's ask reaches the model** — the abstracted `AgentContext` has
   `objective=None` pre-Requirement, so the triggering message body must be in
   the user message (the bug that caused `[]`/did-nothing).
4. **Parsing robustness** — handles `{"actions":[...]}` envelope, a bare array,
   markdown-fenced JSON, an empty array, and a malformed/element-shape reply
   WITHOUT panicking.
5. **Policy gate still governs** — any action the model emits is validated +
   audited; an illegal action becomes a `PlanActionRejected`, not silent.
6. **Cost attribution** — metering from OpenAI-shaped usage lands a
   `CostIncurred`; `estimated_usd` + cache split are computed; spend is
   attributable.
7. **Diagnostics** — a failed pass produces exactly ONE audited
   `OrchestrationRun` (the double-audit bug).
8. **Harness guards** — when paused or budget-halted, NO provider call is made
   (no spend) before dispatch.
9. **Not hijacked** — the orchestrator drives OWNER messages only; other trigger
   types still go through the deterministic path (idempotence/no-unexpected-calls).

## Planned new tests (all stub-based unless noted)

### A. Prompt contract vs serde drift (highest value — the `missing field` bug)
- **`every_action_in_prompt_deserializes`**: parse the prompt's own shape lines
  out of `LlmOrchestrator`'s instructions and assert each emits a `PmAction`
  that round-trips through serde with the exact fields/values listed. Guards the
  enum field/name drift before it ever reaches a live model.
- **`prompt_lists_required_fields`**: assert the prompt contains the field names
  the serde type actually requires (e.g. `send_message` block includes `"to"`).

### B. Parse robustness (the `[]` / no-op bug)
- **`replies_parse_bare_array`** — stub returns `[...]` (no envelope) → actions
  extracted.
- **`replies_parse_markdown_fenced_json`** — stub wraps content in ```json ```
  → still parses (defensive strip holds).
- **`empty_actions_is_valid_noop`** — stub returns `{"actions":[]}` → no
  actions, no error, no panic, but the pass is still audited.

### C. Policy gate on LLM output (the live assign/start rejection)
- **`gate_rejects_illegal_llm_action_and_audits`**: stub returns a MIX of one
  legal (`create_task`) and one illegal (e.g. `assign_task` to an un-hired id,
  or `complete_task` on an un-started task) → assert the legal one applied AND
  the illegal one produced a `PlanActionRejected` — the whole failure is visible
  in the audit trail, not silent.
- **(behavior choice) partial-failure policy**: decide whether one bad element
  in a multi-action reply should fail the whole pass (current: yes, whole parse
  errors) or drop-just-the-good. Recommendation: keep whole-pass-fails (fail
  closed, matches "an LLM can only do what it's authorized to" + loud audit),
  but test it explicitly rather than leave it implicit.

### D. Harness guard — no spend when blocked
- **`paused_or_budget_halt_skips_provider_call`**: set `WorkPaused` (or a
  `BudgetSet` already exceeded) on the projection, then trigger an owner message
  → assert `drive_pm` produced zero `CostIncurred` AND zero HTTP hits to the
  stub (count requests in the stub). Guards the guard.

### E. Not-hijacked / non-owner triggers
- **`only_owner_messages_route_through_orchestrator`**: append a
  `DecisionMade` (owner) or other non-message event → assert the orchestrator is
  NOT called (stub counters), i.e. orchestration stays scoped to owner messages
  (idempotence / no surprise calls = no surprise spend).

### F. Cost math (attributability)
- **`cost_metering_derives_usd_and_cache_split`** (unit): given a known usage +
  prices, assert `estimated_usd = (prompt*in + completion*out)/1e6`,
  `cache_read = cached_tokens`, and the `CostIncurred` lands provider/model. Round
  out the cache-write/ratio path if `cache_creation_input_tokens` ever reports.

### G. Transport / error (resilience)
- **`provider_http_error_is_audited_no_panic`**: stub returns HTTP 500 / bad
  status → orchestrator returns `Err`, audited exactly once, no panic, no spend
  beyond the failed call.

### H. (Opt-in, LOCAL ONLY) live integration
- **`live_openrouter_round_trip`**: an `#[ignore]`d test (or gated on
  `CAST_LLM_API_KEY` being set + a `CAST_LIVE=1` opt-in, so CI never runs it)
  that points at the REAL OpenRouter base_url and asserts a real
  create-task-on-board + CostIncurred, using a min-budget model. This is the
  artifact that caught all three bugs; formalize it so Ben can run it on demand
  without the manual curl dance.

## Not in scope (deliberately)
- Advisor (`/api/advisor`) LLM replies — their wiring is a separate D2 sub-seam,
  currently deterministic; test that when the LLM is actually connected there.
- Multi-turn conversation-state tests until a real provider round-trips them.
- Querying OpenRouter's *pricing* API to build a live price map — out of scope;
  prices stay configured.

## Test infrastructure
- Extend the stub `boot_stub` so it can (a) return a chosen status code, (b)
  COUNT requests (an `Arc<AtomicUsize>`) for the "no call when guarded" and
  "not hijacked" assertions, and (c) serve a scripted sequence of `content`
  values for multi-action cases.
- Keep everything on `127.0.0.1:0` ephemeral ports, plain `#[tokio::test]`, and
  a `remove_var`-and-restore guard around any env mutation (tests run
  concurrently).

## Success criteria
- `make` stays green; test count grows from 280 → ~292; clippy `-D warnings` clean.
- No live key required for CI; the live test is opt-in and documented.
- Every bug the smoke-test found has an equivalent automated guard.
