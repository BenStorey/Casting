# Web First-Run Setup Wizard — Implementation Plan

> **For Hermes:** implement with TDD; commit; push.

**Goal:** the phone-testable first-run UI. When a company isn't configured yet
(only the PM hired), the SPA shows a **setup wizard** (name, objective, choose
cast roles, optional owner token). On submit it drives the SAME `setup` engine
we built for the CLI, then lands on the live dashboard. "Both CLI + UI, one
engine" made real.

## The "is it set up?" signal

`cast run` always seeds `ProjectCreated` + the PM. So the company is
**unconfigured** when there are no non-PM agents yet. The frontend shows the
wizard while `agents.filter(id !== 'pm')` is empty.

## Backend (new web endpoints over the setup engine)

- `AppState` gains `state_dir: Option<PathBuf>` (set in main.rs) so the web
  setup can persist `config.json`.
- `setup.rs`: refactor agent-id resolution out of `SetupPlan::build` into a
  shared `resolve_hires(roles)`; add `ensure_hires(state, roles)` (idempotent —
  skip already-hired) and `persist_config(dir, name, token)`.
- `web.rs`:
  - `GET /api/setup/status` → `{ configured: bool, roles: [{id,title,scope}] }`
    (the role catalog, so the UI lists checkboxes).
  - `POST /api/setup` `{name, objective, cast:[role ids], owner_token?}` →
    validate roles, hire cast idempotently, persist config, then append a
    **owner `MessageSent` with the objective** (which triggers `plan_onboard`).
    Returns `{hires: [...], objective}`.
- `main.rs`: pass the state-dir to AppState.

## Frontend

- `api.ts`: `fetchSetupStatus()`, `submitSetup(...)` types + calls.
- `App.tsx`: if `state.agents` has no non-PM agent, render `<SetupWizard>`
  (full-screen onboarding) instead of the tabs; on submit → submitSetup →
  refresh → live dashboard. Keep the chat fallback if the user dismisses.
- `SetupWizard.tsx`: name input, objective input, role checkboxes (from
  `/api/setup/status`), optional owner-token, a "Launch" button, and a live
  status line ("hiring Marcus…").
